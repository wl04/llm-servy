# LLM Servy

[English](README.md) · Русский

Windows-приложение с управлением из трея для запуска **llama.cpp в Windows** и **DeepSeek Harness в WSL**.

## Возможности

- Выбор моделей из INI в указанной папке.
- Фоновый запуск сервисов с журналом в окне приложения.
- Подключение к работающим серверам; приложение останавливает только запущенные им процессы.
- Управление из трея и интерфейс на русском или английском.

## Требования

- Windows x64 и [.NET Desktop Runtime 10 x64](https://dotnet.microsoft.com/en-us/download/dotnet/10.0). В разделе **.NET Desktop Runtime** выберите **Windows → x64**. Runtime не включён в приложение; SDK нужен только для сборки из исходников.
- [Сборка llama.cpp для Windows](https://github.com/ggml-org/llama.cpp/releases), соответствующая вашему оборудованию (CPU, CUDA или Vulkan).
- Модели и INI-пресеты, совместимые с установленной версией llama.cpp и вашим оборудованием.
- [Дистрибутив WSL](https://learn.microsoft.com/en-us/windows/wsl/install) с Bash, Python 3 и Node.js с npm/npx, совместимыми с выбранной версией DeepSeek Harness.

Для установки WSL с Ubuntu выполните `wsl --install -d Ubuntu` в **PowerShell от имени администратора**, перезагрузите компьютер, если потребуется, затем откройте Ubuntu и создайте пользователя Linux.

LLM Servy использует указанную версию DeepSeek Harness в WSL. Если она не установлена и отсутствует в кеше, npx скачивает её при первом запуске; для этого нужен доступ к сети. Оболочка входа WSL должна находить Node.js и Python.

## Быстрый запуск

1. Скачайте ZIP приложения для Windows x64 из [Releases](https://github.com/wl04/llm-servy/releases), распакуйте весь архив в папку и запустите `llm-servy.exe`. Выбирайте архив приложения, а не **Source code**; установщик не требуется.
2. В **Настройках** выберите папку моделей и INI, папку llama.cpp, дистрибутив WSL и существующую рабочую папку harness в WSL. Укажите точную версию пакета DeepSeek Harness.
3. Выберите модель, нажмите **Запустить**, затем **Открыть DeepSeek Harness**, когда кнопка станет доступна.
4. В DeepSeek Harness настройте провайдер: укажите адрес API llama.cpp по инструкции [ниже](#сеть-windows-и-wsl) и идентификатор модели из секции INI, затем выберите эту модель. LLM Servy не редактирует настройки провайдера harness.

Порты по умолчанию: **1234** для llama.cpp и **3080** для веб-интерфейса harness. Крестик скрывает окно в трей; **Выход** останавливает запущенные приложением сервисы и закрывает его.

## Сеть Windows и WSL

Лаунчер и llama.cpp работают в Windows, а DeepSeek Harness — в WSL. Открытие веб-интерфейса harness в браузере Windows ещё не подтверждает, что harness может подключиться к API модели.

Укажите адрес API в настройках провайдера harness с учётом сетевого режима WSL (замените порт `1234`, если он изменён):

- **WSL2 NAT:** используйте `http://<IP-хоста-Windows>:1234/v1`. IP хоста можно узнать в WSL командой `ip route show default` — это адрес после `via`. llama.cpp должен слушать интерфейс, доступный из WSL; адрес по умолчанию `0.0.0.0` охватывает все IPv4-интерфейсы, а доступ регулируется брандмауэром Windows.
- **WSL2 mirrored:** используйте `http://127.0.0.1:1234/v1`; llama.cpp можно привязать к `127.0.0.1`, чтобы ограничить доступ локальным интерфейсом loopback.

`0.0.0.0` — адрес прослушивания сервера, а не адрес API для подключения harness. Подробнее — в [руководстве Microsoft по сети WSL](https://learn.microsoft.com/en-us/windows/wsl/networking).

## Настройки

LLM Servy передаёт INI-файлы напрямую в llama.cpp через `--models-preset`, используя его [штатный формат пресетов моделей](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md#model-presets). Формат поддерживается в Windows и Linux; те же пресеты можно использовать без лаунчера.

- Читаются только INI непосредственно в выбранной папке моделей. Пути к моделям внутри INI отсчитываются от папки этого INI.
- Приложение, INI и файлы моделей могут находиться в разных местах. Рабочая папка harness задаётся отдельно.
- Пустое поле папки llama.cpp включает автоматический поиск исполняемого файла. В явно указанной папке ищется `llama-server.exe`, затем `llama.exe`.
- Изменения параметров сервисов применяются при следующем запуске. **Настройки → Интерфейс → Язык** меняет язык после сохранения без перезапуска сервисов. Системный режим выбирает русский для русской Windows и английский в остальных случаях.

Настройки: `%LOCALAPPDATA%\llm-servy\settings.json`. Журнал: `%LOCALAPPDATA%\llm-servy\logs\launcher.log`. Оба файла открываются из **Настроек**. Токены входа в harness хранятся в памяти и скрываются в журнале; вывод сервисов сохраняется на исходном языке.

## Обновление

Завершите LLM Servy через меню трея, распакуйте новый релиз в отдельную папку и запустите приложение из неё. Настройки остаются в `%LOCALAPPDATA%\llm-servy` и подхватываются автоматически.

## Сборка из исходников

Используйте терминал Windows в корне репозитория. Версия SDK указана в [global.json](global.json).

```powershell
dotnet build llm-servy.slnx
.\publish.ps1
```

Приложение написано на C# с WinForms на .NET 10. Отладка, тесты, архитектура, локализация и импорт настроек описаны в [руководстве разработчика](docs/development.md) на английском.

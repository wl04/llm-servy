# LLM Servy

[English](README.md) · Русский

Windows-приложение с управлением из трея для запуска **llama.cpp в Windows** и **DeepSeek Harness или Pi в WSL**.

## Возможности

- Выбор моделей из INI в указанной папке.
- Выбор harness с отдельной рабочей папкой для каждого.
- DeepSeek Harness в браузере; Pi в Windows Terminal с сохраняющимися tmux-сессиями.
- Статусы сервисов, журнал и управление из трея.
- Интерфейс на русском и английском.

## Требования

### Общие

- Windows x64 и [.NET Desktop Runtime 10 x64](https://dotnet.microsoft.com/en-us/download/dotnet/10.0). В разделе **.NET Desktop Runtime** выберите **Windows → x64**. Runtime не включён в приложение; SDK нужен только для сборки из исходников.
- [Сборка llama.cpp для Windows](https://github.com/ggml-org/llama.cpp/releases), соответствующая оборудованию, а также совместимые модели и INI-пресеты.
- [Дистрибутив WSL](https://learn.microsoft.com/en-us/windows/wsl/install) с Bash, Python 3 и Node.js, совместимым с выбранным harness. Эти команды должны быть доступны в оболочке входа WSL.

Для установки Ubuntu в WSL выполните `wsl --install -d Ubuntu` в **PowerShell от имени администратора**, перезагрузите компьютер, если потребуется, затем откройте Ubuntu и создайте пользователя Linux.

### Для выбранного harness

| Harness | Дополнительные требования |
| --- | --- |
| [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness/blob/master/README.md) | npm/npx в WSL. LLM Servy использует указанную версию пакета; если она недоступна локально, npx скачивает её при первом запуске. Для этого нужен доступ к сети. |
| [Pi](https://pi.dev/docs/latest/quickstart) | Установленный Pi в WSL, tmux 3.2+ (`sudo apt install tmux` в Ubuntu) и [Windows Terminal](https://learn.microsoft.com/en-us/windows/terminal/install) в Windows. Pi и tmux должны быть доступны в оболочке входа WSL. LLM Servy не устанавливает Pi. |

## Быстрый запуск

1. Скачайте ZIP приложения для Windows x64 из [Releases](https://github.com/wl04/llm-servy/releases), распакуйте весь архив и запустите `llm-servy.exe`. Выбирайте архив приложения, а не **Source code**; установщик не требуется.
2. В **Настройках** выберите папку моделей и INI, папку llama.cpp, дистрибутив WSL и существующую рабочую папку выбранного harness.
3. Выберите harness и модель на главном экране. Выполните настройку выбранного harness по инструкции ниже.

LLM Servy не редактирует настройки провайдеров и учётные данные harness. Используйте [адрес API для вашего сетевого режима WSL](#сеть-windows-и-wsl). ID модели должен совпадать с **именем секции INI**, которое может отличаться от имени файла модели.

- **DeepSeek Harness:** укажите точную версию пакета в Настройках. Нажмите **Запустить**, затем **Открыть DeepSeek Harness**. В его веб-интерфейсе настройте провайдер llama.cpp и ID модели, затем выберите эту модель.
- **Pi:** **до нажатия «Запустить»** настройте в Pi провайдер и выбранную модель; см. [настройку моделей Pi](https://pi.dev/docs/latest/models). В **Настройки → Pi** укажите исполняемый файл и точное имя провайдера из этой конфигурации. Нажмите **Запустить**, затем **Открыть Pi**. LLM Servy передаёт в Pi имя провайдера и ID выбранной модели.

## Управление сервисами

Одновременно управляется один harness. LLM Servy может подключаться к уже работающим серверам llama.cpp и DeepSeek Harness; останавливает только запущенные им процессы. Независимо запущенные сессии Pi под управление приложения не переходят.

| Действие | Результат |
| --- | --- |
| **Запустить** | Запускает llama.cpp или подключается к нему, загружает выбранную модель, затем запускает выбранный harness или подключается к нему. Для Pi всегда создаётся управляемая сессия. |
| **Открыть DeepSeek Harness** | Открывает веб-интерфейс. |
| **Открыть Pi** | Подключается к работающей сессии Pi или создаёт новую после завершения Pi, без перезапуска llama.cpp и повторной загрузки модели. |
| Закрыть терминал Pi | Оставляет Pi работать; повторное открытие подключает к нему. |
| Выйти из Pi через `/quit` или сочетание клавиш | Завершает Pi, оставляя llama.cpp работать. Терминальные клиенты отключаются успешно; закрытие вкладки зависит от настроек Windows Terminal. |
| **Остановить** | Останавливает сервисы, запущенные LLM Servy. |
| Закрыть окно LLM Servy | Скрывает приложение в трей. |
| **Выход** в трее | Останавливает управляемые сервисы и закрывает LLM Servy. |

Статус Pi отражает состояние процесса, а не то, думает ли агент или ожидает ввода. Новый процесс Pi не восстанавливает предыдущую беседу автоматически. Для продолжения после остановки Pi, WSL или Windows используйте сохранённые сессии самого Pi.

## Сеть Windows и WSL

Лаунчер и llama.cpp работают в Windows, а harness — в WSL. Открытие веб-интерфейса DeepSeek Harness из Windows ещё не подтверждает его доступ к API модели.

Порты по умолчанию: **1234** для llama.cpp, **3080** для веб-интерфейса DeepSeek Harness. Укажите адрес API в настройках провайдера harness с учётом сетевого режима WSL, заменив `1234`, если порт изменён:

- **WSL2 NAT:** `http://<IP-хоста-Windows>:1234/v1`. IP хоста можно узнать в WSL командой `ip route show default` — это адрес после `via`. llama.cpp должен слушать интерфейс, доступный из WSL. Адрес привязки по умолчанию `0.0.0.0` охватывает все IPv4-интерфейсы; доступ регулируется брандмауэром Windows.
- **WSL2 mirrored:** `http://127.0.0.1:1234/v1`. llama.cpp можно привязать к `127.0.0.1`, чтобы ограничить доступ локальным интерфейсом loopback.

`0.0.0.0` — адрес прослушивания сервера, а не адрес API для подключения. Подробнее — в [руководстве Microsoft по сети WSL](https://learn.microsoft.com/en-us/windows/wsl/networking).

## Настройки

### Модели и INI

LLM Servy передаёт INI-файлы напрямую в llama.cpp через `--models-preset`, используя его [штатный формат пресетов моделей](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md#model-presets). Формат работает в Windows и Linux; пресеты можно использовать и без LLM Servy.

- Читаются только INI непосредственно в выбранной папке моделей. Относительные пути к моделям отсчитываются от папки INI.
- Приложение, INI и модели могут храниться отдельно. У каждого harness своя рабочая папка, которую также можно выбрать на главном экране до запуска.
- В явно указанной папке llama.cpp ищется `llama-server.exe`, затем `llama.exe`. Если не заданы ни папка, ни сохранённый путь к исполняемому файлу, автоматический поиск ищет `llama.exe` в PATH и ссылках на приложения Windows; для `llama-server.exe` укажите папку явно.

### Параметры и журналы

Изменения параметров сервисов применяются после **Остановить → Запустить**. Повторное открытие завершившегося Pi сохраняет параметры текущего запуска. **Настройки → Интерфейс → Язык** применяется после сохранения без перезапуска сервисов; системный режим выбирает русский для русской Windows и английский в остальных случаях.

Настройки хранятся в `%LOCALAPPDATA%\llm-servy\settings.json`, журнал — в `%LOCALAPPDATA%\llm-servy\logs\launcher.log`. Оба файла открываются из **Настроек**. Сообщения лаунчера локализованы; вывод сервисов сохраняется на исходном языке. Переписка Pi остаётся в терминале, а события запуска и завершения записываются в журнал лаунчера. Токены входа в веб-интерфейс DeepSeek Harness хранятся в памяти и скрываются в журнале.

## Обновление

Завершите LLM Servy через меню трея, распакуйте новый релиз в отдельную папку и запустите приложение из неё. Существующие настройки подхватываются автоматически.

## Сборка из исходников

Используйте терминал Windows в корне репозитория и SDK, указанный в [global.json](global.json):

```powershell
dotnet build llm-servy.slnx
.\publish.ps1
```

Приложение использует C# и WinForms на .NET 10. Результаты сборки, отладка, тесты, архитектура, локализация и импорт настроек описаны в [руководстве разработчика](docs/development.md) на английском.
